# Requirement To Testcases Core

## 目标
在信息不完整的情况下，先稳定产出可评审的核心用例，避免一次性生成过多低价值细节。

## 何时使用
- 用户要求把需求拆成测试用例
- 用户强调按参考模板或按XMind层级输出
- 用户需要先看主流程和关键分支

## 输入
- 需求文档、评审纪要、接口说明、原型说明（任一或组合）

## 快速使用
1. 先将 docx 转为 md：`python docx_to_md.py "需求.docx" "需求.md"`
2. 在对话中附带 `@需求.md`
3. 指令示例：基于 `@需求.md` 输出核心测试用例（仅 p0/p1），保存为 `xxx-core.md`

## 输出范围（强制）
- 只输出 `p0/p1` 用例
- 使用固定层级：
  - `# 文档标题`
  - `## 一级业务域`
  - `### 二级功能块`
  - `#### 正常流程功能` / `#### 关键分支（顺序）`
  - `- tc-pX-001：标题`
    - `- 场景/操作`
      - `- 预期结果`

## 编号规则（强制）
- 格式：`tc-p0-001`、`tc-p1-001`
- 在同一 `### 二级功能块` 内按优先级独立递增
- 不允许重复编号
- 若后续 full 开启模板对齐并采用短编号，core 仍保持本规则，不强制跟随模板

## 核心流程
1. 提取功能块（按可测目标拆成 `###`）
2. 为每个功能块生成 `p0` 主流程
3. 识别顺序依赖并生成 `p1` 关键分支（必须按时序）
4. 对缺失信息生成“最小待澄清清单”（最多5条）

## 待澄清规则
- 高影响待澄清项 >= 3：暂停扩写，先向用户确认
- 否则继续生成并在用例中标记 `【假设：...】`

## 禁止项
- 不输出 p2/p3（交由扩展技能处理）
- 不输出完整性检查报告（交由审计技能处理）
- 不使用表格
