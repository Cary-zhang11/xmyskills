# Testcases Expand Coverage

## 目标
基于 core 结果补全扩展维度，避免主流程被低优先级场景淹没。

## 前置输入
- 推荐输入：`{需求名}-core.md`
- 可附加输入：原始需求文档或新增变更说明

## 快速使用
- 在对话中附带 `@{需求名}-core.md`
- 指令示例：基于 `@{需求名}-core.md` 补齐 p2/p3，并补 UI验证、浮层场景、网络相关、机型兼容，输出 `xxx-full.md`

## 输出范围（强制）
- 仅补充 `p2/p3` 与专项维度
- 保持原有层级与术语，不重写已有 `p0/p1`
- 若提供模板并开启模板对齐验收，允许按模板章节组织 full（可包含 p0/p1/p2/p3 完整集）
- 模板模式下优先确保“功能块拆分一致性”和“测试维度完整性”

## 优先补充维度
- `#### UI验证` — 文案、布局、样式、按钮动效等视觉校验
- `#### 浮层场景` — 弹层关闭、外点关闭、返回等交互
- `#### 网络相关` — 接口高延迟、超时、断网、弱网幂等
- `#### 机型兼容` — 屏幕适配、横竖屏切换、折叠屏
- 必要时补：`#### 数据展示边界`、`#### 触区范围`、`#### 手势冲突`、`#### 图片缺失`、`#### 数据刷新`、`#### 版本控制`、`#### 特殊字符`

## 维度覆盖要求（强制）
每个 `### 二级功能块` 下，除 `#### 正常流程功能` 和 `#### 关键分支（顺序）` 外：
- 必须补充 `#### UI验证`（至少1条用例）
- 必须补充 `#### 浮层场景`（至少1条用例，涉及弹层的功能块）
- 必须补充 `#### 网络相关`（可在 `## 网络相关` 或 `## 机型兼容` 章节集中覆盖，但每个功能块的接口均需覆盖高延迟/超时场景）

## 禁止的 placeholder 内容（强制）
以下模板化骨架内容视为无效生成，必须基于需求文档推导具体测试内容：
- "主流程验证" / "进入当前功能块并完成关键操作" / "主链路可达且结果正确"
- "关键分支兜底" / "触发异常或边界路径" / "按规则兜底并可继续流程"
- "UI呈现与状态校验" / "检查关键控件样式与文案" / "展示符合需求并可交互"
- "浮层开关与回退" / "触发并关闭相关弹层" / "关闭后状态保持正确"
- "弱网与超时处理" / "模拟高延迟、超时、弱网重试" / "提示清晰且操作可恢复"
- "多机型适配" / "小屏、横竖屏、折叠屏访问" / "布局稳定且功能可达"

## 编号规则
- 格式：`tc-p2-001`、`tc-p3-001`
- 在同一 `### 二级功能块` 内独立递增
- 禁止与既有编号冲突
- 若模板为 `tc-pX` 短编号，full 可跟随模板短编号风格

## 补全流程
1. 读取核心用例，锁定每个功能块
2. 对每个功能块补 `p2/p3`，不改 `p0/p1` 语义
3. 网络相关统一按“高延迟/超时/弱网幂等”三类补齐
4. 机型兼容至少覆盖“屏幕适配、横竖屏、折叠屏”
5. 若提供模板：以模板 `##/###` 为拆分基线补齐 full，优先保证功能块拆分一致

## 输出要求
- 仍使用可转XMind的Markdown层级
- 不输出完整性检查报告（交由审计技能）
- 统一风格与编号见 [../_shared/testcase-style.md](../_shared/testcase-style.md)
- 若模板对齐模式开启，full 需优先满足模板结构覆盖，再补齐专项维度
- 模板对齐模式下：编号格式可不同，但功能拆分和维度缺失不可接受
- 模板对齐模式下：若模板存在独立 `## 网络相关` 或 `## 机型兼容`，full 必须同步产出对应章节
