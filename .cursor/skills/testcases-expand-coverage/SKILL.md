# Testcases Expand Coverage

## 目标
基于 core 结果补全扩展维度，避免主流程被低优先级场景淹没。

## 前置输入
- 推荐输入：`{需求名}-core.md`
- 可附加输入：原始需求文档或新增变更说明

## 快速使用
- 在对话中附带 `@{需求名}-core.md`
- 指令示例：基于 `@{需求名}-core.md` 补齐 p2/p3，并补 UI验证、浮层场景、网络相关、机型兼容，输出 `xxx-full.md`

## 输出范围（强制）
- 仅补充 `p2/p3` 与专项维度
- 保持原有层级与术语，不重写已有 `p0/p1`

## 优先补充维度
- `#### UI验证`
- `#### 浮层场景`
- `#### 网络相关`
- `#### 机型兼容`
- 必要时补：数据边界、触区范围、手势冲突、图片缺失

## 编号规则
- 格式：`tc-p2-001`、`tc-p3-001`
- 在同一 `### 二级功能块` 内独立递增
- 禁止与既有编号冲突

## 补全流程
1. 读取核心用例，锁定每个功能块
2. 对每个功能块补 `p2/p3`，不改 `p0/p1` 语义
3. 网络相关统一按“高延迟/超时/弱网幂等”三类补齐
4. 机型兼容至少覆盖“屏幕适配、横竖屏、折叠屏”

## 输出要求
- 仍使用可转XMind的Markdown层级
- 不输出完整性检查报告（交由审计技能）
- 统一风格与编号见 [../_shared/testcase-style.md](../_shared/testcase-style.md)
