# Testcases Audit Report

## 目标
独立生成审计报告，避免把“报告逻辑”耦合在用例生成过程中。

## 前置输入
- 推荐输入：`{需求名}-full.md`
- 必要对照：原始需求文档（用于统计覆盖）

## 快速使用
- 在对话中附带 `@{需求名}-full.md` 和 `@{需求名}.md`
- 指令示例：对 `@{需求名}-full.md` 与 `@{需求名}.md` 生成完整性检查报告，输出 `xxx-audit.md`

## 审计输出结构（强制）
- `## 完整性检查报告`
  - `### 1. 需求覆盖统计`
  - `### 2. 用例覆盖度检查`
  - `### 3. 维度覆盖检查`
  - `### 4. 关键信息提取确认`
  - `### 5. 待澄清问题汇总`
  - `### 6. 生成质量评估`
  - `### 7. 输出文件信息`
  - 文末必须包含 `### 统计口径说明`：说明功能点统计口径、用例数量统计方式、维度覆盖检查方式、模板对比范围

## 统计口径（强制）
- 需求功能点数：输入需求中可测试的二级功能块数量
- 生成功能点数：输出文档中 `###` 数量
- 功能点覆盖率：生成功能点数 / 需求功能点数
- 报告中必须注明“统计口径说明”

## 必查项
- 覆盖优先级：p0/p1/p2/p3 是否齐全
- 编号规范：是否唯一、是否连续
- 参数提取：`bt`、`tag`、`posid`、版本差异、环境差异
- 假设风险：`【假设：...】` 是否集中在高影响模块

## 风险结论规则
- 若高影响待澄清项 >= 3：结论标记“高风险，建议先澄清再提测”
- 若编号冲突或覆盖率 < 90%：结论标记“不可直接提测”
- 其余情况可标记“可提测，附风险清单”
