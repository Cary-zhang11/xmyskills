# Testcase Style Contract

## 术语统一
- 统一使用：功能点、关键分支、UI验证、浮层场景、网络相关、机型兼容、预期结果
- 禁止同义词混用导致结构漂移

## 层级统一（XMind 友好）
- `# 文档标题`
- `## 一级业务域`
- `### 二级功能块`
- `#### 测试维度`
- `- tc-pX-001：标题`
  - `- 场景/操作`
    - `- 预期结果`

## 编号统一
- `tc-p0-001`、`tc-p1-001`、`tc-p2-001`、`tc-p3-001`
- 同一 `### 二级功能块` 内按优先级独立递增
- 编号必须唯一

## 输出约束
- 不使用表格输出用例正文
- 必须有可验证预期结果
- 遇到缺失信息可用 `【假设：...】` 标记

## QA验收优先级（通用）
- P1：功能拆分完整性（业务域/功能块/关键分支不缺失）
- P1：测试维度完整性（UI验证、浮层场景、网络相关、机型兼容）
- P2：编号规范与样式一致性（允许 warning，不默认阻塞）
