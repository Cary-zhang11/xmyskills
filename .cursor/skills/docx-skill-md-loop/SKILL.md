# Docx Skill Md Loop

## 目标
将需求文档按固定流程生成测试用例，并通过多轮校验持续优化，直到达到验收标准或达到轮次上限。

## 适用场景
- 用户要求“先生成，再校验，再优化，再生成”的循环流程
- 用户要求 `full.md` 与模板“基本一致”（功能拆分和维度优先）
- 用户要求限制轮次（例如先跑 3 轮看效果）

## 输入
- 必需：`@xxx.docx`
- 可选：`@xxx-模板.md`（仅用于 `full` 对齐验收）
- 可选：最大轮次 `N`（默认 3）

## 输出
- `{需求名}.md`
- `{需求名}测试用例-core.md`
- `{需求名}测试用例-full.md`
- `{需求名}测试用例-audit.md`
- `{需求名}测试用例-迭代报告.md`

## 一轮执行步骤（强制）
1. 执行 docx 转 md
2. 清理上一轮产物标记（至少确认 `full.md` 将被覆盖为新内容）
3. 按 pipeline 生成 core/full/audit（必须由 skill 生成，不允许模板直拷贝）
3. 执行校验：
   - 通用校验：`core/full/audit`
   - 模板校验：仅 `full vs 模板`（若提供模板）
4. 记录本轮报告（通过/失败项/下一轮动作）
5. 未通过则进入下一轮，直到通过或到达最大轮次

## 生成约束（强制）
- 禁止使用临时脚本（python/ps1/bash）直接写入或覆盖 `core/full/audit`
- 禁止模板直拷贝生成 `full.md`
- 若检测到 `full` 与模板正文完全一致，判定本轮无效，必须重跑
- 每一轮都必须“重新生成” `core/full/audit`，禁止复用上一轮文件直接做校验
- 仅校验未重生成的轮次，判定为无效轮次，不计入通过结果

## 验收优先级（QA口径）
- P1：功能拆分完整性（业务域/功能块覆盖）
- P1：测试维度完整性（UI验证、浮层场景、网络相关、机型兼容）
- P2：编号样式一致性（`tc-pX` 与 `tc-pX-001`，默认非阻塞）

## 通过标准（默认）
- 通用校验通过
- 若有模板：`full` 对模板结构覆盖率达标（以校验脚本门槛为准）
- 失败项可定位并写入迭代报告
- 且本轮产物来源必须可追溯为 skill 生成（非脚本直写、非模板拷贝）

## 失败处理规则
- 禁止跳过失败项直接宣称通过
- 每轮仅修改“通用 skill 规则”，禁止写死当前业务特例
- 若达到最大轮次仍失败，输出“剩余差异清单 + 建议修复顺序”

## 推荐命令
```powershell
powershell -ExecutionPolicy Bypass -File "run_pipeline.ps1" "D:/path/需求.docx" -TemplatePath "D:/path/需求测试用例-模板.md" -MaxRounds 3 -NonInteractive
```

## 调用提示词
```text
使用 docx-skill-md-loop：
对 @xxx.docx 执行 3 轮迭代生成与校验；若提供 @xxx-模板.md，仅做 full 对齐验收。
每轮都必须重新生成用例，不允许模板直拷贝覆盖 full。
输出每轮结论和最终差异清单。
```
